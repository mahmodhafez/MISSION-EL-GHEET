## Proposed exchange records

| Record and key | Required fields and definitions | Producer → consumer |
|---|---|---|
| Source snapshot · snapshot_id | Dataset, API version, exact URL and parameters, requested lat/lon, returned lon/lat/elevation, elevation override if used, community, time standard, covered dates, retrieval UTC, source families, units map, fill, raw and data/metadata hashes, messages, raw file reference. Unpublished source release metadata stays unknown. | Refaat → all, Karim for caching |
| Daily weather · snapshot_id + locality_id + local_solar_date | tmax_c, tmin_c, tmean_power_c, tdew_c, rhmean_pct, wind2m_m_s, pressure_kpa, rs_mj_m2_day, missing parameters, QC flags, heat_input_valid and et0_primary_input_valid. Preserve raw values and use null for cleaned missing data. | Refaat → Mahmoud |
| Locality · locality_id | Site purpose (research reference, field or station), latitude, longitude, elevation_m and its source, coordinate source, separate meteorological and solar grid support, daily convention. | Refaat → Mahmoud, Karim, Moaaz |
| Crop rule · rule_id + version | Locality, species, cultivar/type, purpose, window, stage evidence, maturity and harvest meaning, release and preparation definitions, soil measurement/unit, constraints, reviewer/date, source and activation status. Each farmer commitment records locked cut dates, purpose, first free day and confirmation. | Refaat sources → Yahya owns constraints → Karim, Moaaz |
| ET₀ daily · snapshot_id + local_solar_date + method_version | et0_mm_day, humidity_route, radiation_route, input_mask, method_status, reference-check version and diagnostic intermediate values. | Mahmoud → Refaat for labels, replay, Karim |
| Replay · block_id + plan_id + slot | Start, first free day, prep span, crop/purpose, locks, split/origin, weather snapshot, frozen threshold ID, valid/expected days by metric, exceedance count/share/degree-days, ET₀ total and mean and reason for exclusion. | Yahya supplies plan, Refaat supplies weather and masks, Mahmoud owns evaluation |
| Forecast examples · locality_id + issue_at_utc + target_date + target_name | Horizon from issue day, input snapshot, latest event date, available_at or assumed-lag flag, units, eventual label, mask and chronological fold. Flag covariates known in advance. | Refaat → Mahmoud, Amr reviews claims |
| Station provenance · station_id + source_version | True coordinates/elevation, distance, observing day, variables/units, flags, overlap and missing counts, instrumentation/relocations, permission, dissemination and possible upstream links to POWER. | Refaat sources → Mahmoud assesses attribution and bias |

Adopt **[sowing day, first free day)** as a proposed occupancy convention. A final cut can still occupy its day. Confirm when the field becomes free and preserve the preparation interval so consecutive crops do not double-book the same day. Keep a daily weather label distinct from a forecast issue time or a retrieval timestamp. ## Acceptance checks for the handoff

| Check | Acceptance condition and response to failure |
|---|---|
| Dates and identity | One distinct record per expected date and frozen series. Check leap days, inclusive endpoints, coordinate order, overlaps and gaps. Resolve conflicting revisions by explicit snapshot. |
| Units and fill | Read the sentinel before physical range checks. In the sample, AG shortwave was MJ/m²/day and pressure kPa. Treat genuine zero as a value. Quarantine unknown units and flag outlying values with their recorded provenance. [POWER AG dictionary](https://power.larc.nasa.gov/api/system/manager/parameters?community=AG&temporal=daily) · [Sakha 2020 POWER response](https://power.larc.nasa.gov/api/temporal/daily/point?parameters=T2M_MAX,T2M_MIN,T2M,T2MDEW,RH2M,WS2M,PS,ALLSKY_SFC_SW_DWN&community=AG&longitude=30.95&latitude=31.117&start=20200101&end=20201231&format=JSON&time-standard=LST) |
| Physical consistency | Flag Tmin > Tmax, Tmean outside extrema, RH outside 0–100%, negative wind/shortwave, nonpositive pressure, and suspect vapour-pressure or clear-sky ratios. Assess outliers and repeated runs in local and seasonal context. |
| Missingness | Count absent dates, fill, null/nonfinite and physically suspect values separately. Report joint coverage and longest gaps by metric/year/season. Missing radiation can invalidate ET₀ while leaving heat exposure available. |
| Reference calculation | Mahmoud reproduces FAO-56 Example 18 at published precision, checks intermediate terms and the dew-point route independently. Only one versioned ET₀ series feeds downstream labels. [FAO-56 ch. 3](https://www.fao.org/4/x0490e/x0490e07.htm) · [FAO-56 ch. 4](https://www.fao.org/4/x0490e/x0490e08.htm) |
| Hot-day threshold | Record development dates, valid count, Tmax 90th percentile, quantile algorithm and unit. Count strict exceedances, share of valid days and sum positive exceedance in °C·days. Freeze before held-out evaluation. |
| Replay and baseline | The same crop set, restrictions, weather blocks and common valid-date masks apply. Calendar uses sourced earliest dates and fixed minimal-change tie-breaking. Preserve complete chronological blocks, timing-only comparisons, losses and ties. |
| Station evidence | Quarantine the four published SARS weather files until the custodian resolves metadata and dates. Verify the observational day, quality flags, independence and spatial suitability of any replacement. [Publisher’s station archive](https://odjar.org/article/download/16318/17327) · [NOAA station histories](https://www.ncei.noaa.gov/pub/data/noaa/isd-history.csv) · [GHCN-D element and flag guide](https://www.ncei.noaa.gov/pub/data/ghcn/daily/readme.txt) |
| Forecast clock | Observed predictors need an available_at no later than issue time. Label reconstructed delays as retrospective assumptions. Offset the complete gap from the last available day to D+1…D+7. Keep the future verifying weather out of predictors. [NASA archive catalogue](https://data.nasa.gov/dataset/prediction-of-worldwide-energy-resources-power) · [POWER Data Services](https://power.larc.nasa.gov/docs/services/) |
| Reproducibility | Pin software and checkpoint revisions, snapshot ID, rule version, units, metric definitions, split and random seed. Keep source facts, derived values and human approvals traceable. |

A small Python environment is sufficient for daily point data. A standard HTTP client or requests can retrieve JSON, hashlib can identify snapshots and pandas or PyArrow can store tabular outputs. Mahmoud can use Python math/NumPy and pytest for FAO-56 checks. PyTorch, Chronos and PEFT belong in the forecasting experiment environment.

## People and decisions

- **Refaat** owns source validation, metadata, daily inputs, masks and coverage. **Mahmoud** owns ET₀, replay and station evaluation, sensitivity and the separate model experiment.
- **Yahya** owns the rule ledger, field eligibility, locked commitments and calendar baseline. A local agronomist reviews applicability. The farmer confirms commitments, irrigation access and flexibility.
- **Karim** owns APIs, cache identity and deployment. **Moaaz** renders the same source values and uncertainties in Arabic and English. **Amr** owns integration, priorities, ML oversight and claims submitted to judges.
